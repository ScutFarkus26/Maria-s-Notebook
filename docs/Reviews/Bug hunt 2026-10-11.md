# Bug hunt 2026-10-11

> **All fixed** on main in a031f7ab (2026-10-11). Not rolled out. Found at main ee7923e6; the fixes and the review that followed are in <../Plans/Plan - Bug hunt 2026-10-11 fixes.md>.
> In short: a read-only hunt over the oldest code no earlier hunt had read — pre-June lines the 10-10 hunt left unassigned, and everything written June–August and never rewritten — with 77 findings (more counting the smaller items grouped under one number); the worst are a possible album crash, project check-in work that never shows on its project, search going empty for a whole session, and menu items and Siri shortcuts that do nothing.

"Confirmed" means the code path was traced end to end. "Plausible" means the path is real but the trigger depends on timing, data, or something Apple doesn't document.

## Scope

Line ages were measured fresh at ee7923e6 with `git blame -w -M` (every line of 1,748 source files). In scope, about 37,700 lines in 406 files:

- **Pre-June lines the 10-10 hunt didn't assign to anyone** (about 12,000 lines in some 200 files; that hunt's groups took the files with the most old lines).
- **Lines written 2026-06-01 to 2026-08-31 and never rewritten** (the next-oldest code; every hunt since has looked at September–October work or at a single layer).

Left out because they had their own hunts: sync and sharing (10-05), persistence, the data model and backups (10-05), and the Daybook Assistant (10-04). Eight reviewers took one area each. The top findings were checked again against the code by hand before this was written: the album index crash, Uniform project work, search on a deferred launch, the Practice form, recall "Forgotten", the rollover default and New Lesson.

## What runs through all of it

- **Linked work copies read as shared rows.** Quick New Work and `assign_work` make one row per child, and each row lists every classmate as a participant. Code written for project-style shared rows then counts a classmate's copy as the child's own: the Quiet column, the Works log's child filter, and the checklist cells (#18, #19). The planner's `gatingWork` already tells the two apart. The reverse also happens: genuinely shared project work is read by its first chooser only (#76).
- **Requests nobody answers.** `AppRouter` requests that no screen handles, or handles only while it is on screen: New Lesson and Import Lessons (#1), Open Student on iPhone and iPad (#2), New Student on the Mac (#3), anything asked for during a cold launch (#4), and the command bar's Practice form (#45).
- **Children who left, and hidden test students, still shown** — in follow-ups, the Quiet column, the work grid, recall, Spotlight, MCP follow-ups and the project editor (#11, #23, #24, #32, #39, #51, #77).
- **First names alone** where the two Ettys and two Sarahs need "Etty D": Siri replies, Siri's observation summary, and the chat and MCP name lookups (#37, #33, #49).
- **Typed text lost** on a swipe-down, a Cancel, or leaving without Return: command bar captures, template editors, album notes, calendar day notes, project check-in notes and parent reports (#47, #9, #64, #41, #72, #69).
- **Attendance counted without removing duplicates** on the student profile and in parent reports (#34, #74).
