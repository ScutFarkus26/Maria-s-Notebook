## Sync and sharing fixes

1. **"Add them to the share" on a second device can share records already in the share.** Plausible, high. `Sharing/ClassroomSharingService+Setup.swift:57,185`, `SharedStoreOrphanGuard+WaitingList.swift:137-147`. A setup resumed on a device where the pin already exists skips the wait for an import after the pin, and `resumePin` → `notePinMadeHere` clears `pinSeenAt`, so it switches that wait off for the filing step too. On an iPad whose local share data is still half downloaded, `unshared()` counts the Mac's already-shared records as outside, and setup calls `share(_:to:)` on them, the call behind the 2026-09-28 incident. *Fix:* `setupPreflight` refuses while `waitingForImportAfterPin` is true; `resumePin` doesn't clear `pinSeenAt`.
2. **A failed attach marks the wrong store as stopped, so an unrelated success clears it.** Plausible, high. `Services/Sync/CloudKitSyncStatusService.swift:85`. With no store named, `didSet` records `.classroomShare`, but the guide's attaches run against the private store (`.notebook`). His empty shared store's next successful import clears the flag, the dot goes green, and the filing step calls `share(_:to:)` on the dead store again, which can raise an exception Swift can't catch (`ClassroomShareAttach.swift:280`). A second way in: a setup that failed because there was no account yet no longer counts as stopped (`+StoreHealth.swift:45`), but the notebook never rebuilds its stack. *Fix:* name the store from the attach's own store; keep filing paused after an account-less setup until relaunch.
3. **The first pass after updating drops records setup failed to attach, on the device that made the pin.** Confirmed, wrong data, recoverable. `SharedStoreOrphanGuard+WaitingList.swift:119-126`. Older builds never wrote `pinSeenKey`, so the guide's own Mac treats its pin as made elsewhere and forgets records listed before it. They then wait for "Add them to the share" in Settings. *Fix:* when the key is missing and this device already held the pin, record it without forgetting anything.
4. **The name list usually misses the launch import on the notebook.** Plausible, minor. `Sharing/ClassroomNames+Arrival.swift:87,150`, `AppServicesLauncher.swift:129`. `Arrival.start()` begins listening after the launch import has often finished, so folds and waiting names wait for the next import, which can be hours on a quiet Mac. *Fix:* start it when the stores open, or seed it from the buffered early events.

## Name list

5. **A name typed under one Apple Account can land in the next account's row (notebook).** Confirmed, rare. `Sharing/ClassroomNames.swift:115-124`, `ClassroomNames+Zones.swift:319-323`. The undo only runs if the new record name is already known, which it usually isn't yet. Settings also shows the name as saved when it isn't. *Fix:* undo whenever the record name isn't `me`, including when it's unknown; drop the waiting name on an account change, as the Assistant does; report "not saved" on `.nothing`.
6. **Every iCloud download queues another zone lookup behind the one-at-a-time gate.** Confirmed queue, minor. `ClassroomNames+Arrival.swift:109-121`. Nothing merges them, so a name save during a busy morning waits behind all of them. *Fix:* don't queue a second one that hasn't started; warm up only when the import brought name rows.
7. **One stuck lookup stops every name write until relaunch.** Plausible. `ClassroomNames+Zones.swift:232-239,277-297`. The gate is held across `recordIDs(for:)`, which has no time limit. *Fix:* race the lookup against a timeout and treat a timeout as "no answer".

## Meetings: Re-present and Ready for Next

8. **The student record's Meetings tab throws the two decisions away.** Confirmed, wrong data. `Students/Meetings/Tab/StudentMeetingsTab.swift:303,426` → `clearCurrent()` deletes the draft, including `representWorkIDs` / `readyWorkIDs`, without reopening the work or planning anything. The work stays closed and the next lesson never goes On Deck. *Fix:* route both buttons through what `discard` does.
9. **Clearing, or switching a card back to Keep Working, doesn't undo the close.** Confirmed, wrong data. `MeetingDraftModel.swift:153-167,202-219`. Closing through `WorkLogService.log` skips future check-ins, completes linked todos and writes a completion record; logging Working again restores none of it, so the work drops off the Scheduled strip. *Fix:* keep the receipt token and use `WorkLogService.undo`.
10. **Re-present or Ready, then Rest, leaves the work closed.** Confirmed. `MeetingDraftModel.swift:243-248`. *Fix:* reopen it (or undo by token) in `rest()`.
11. **Ready for Next can put a lesson the child already had back On Deck.** Confirmed. `MeetingDraftModel.swift:365-371`. The duplicate check looks only at plans not yet given. *Fix:* skip when she already has a given presentation or a mastery mark for the next lesson.
12. **One child's Re-present flags the whole group's presentation.** Confirmed. `MeetingDraftModel.swift:341-343` sets `needsAnotherPresentation` on the shared record, so every child who had that lesson with her reads as needing reteaching. *Fix:* flag only her own row.
13. **Ready for Next silently does nothing at the end of a sequence.** Confirmed, wrong UI. `MeetingDraftModel.swift:365,380-390`. The work closes as Done but nothing is planned and nothing is said. *Fix:* hide or relabel the button when there's no next lesson; say so on Complete.

## Scheduled strip

14. **Adding days at the front may jump the strip, or keep adding days.** Plausible, needs a look on a device. `Presentations/Planning/WeekPlanSection+Data.swift:60-87`. The "re-pin" sets `leadingDay` to the value it already has, so holding position depends on SwiftUI keeping it by identity. *Fix:* keep the position explicitly, or grow only when scrolling settles.

## MCP check-ins

15. **Moving a check-in can leave two on the same day.** Confirmed. `Services/MCPServer/MCPNotebookTools+WorkCheckIns.swift:217,245-246`. `add_check_in_on` checks the landing day; moving doesn't. *Fix:* refuse for this row, and leave a linked copy where it is and say so.
16. **Two separate assignments to the same children count as one group.** Confirmed in code, needs that data. `Work/Support/WorkGrouping.swift:192-205`. `assign_work` rows never set a presentation, so a repeat assignment weeks later joins the old one; adding a check-in or changing status reaches the old rows too. *Fix:* match only rows made together (`createdAt` within seconds, or a shared group id).
17. **Reopening and adding a check-in in one call is refused.** Confirmed. `MCPNotebookTools+WorkCheckIns.swift:103` runs before `applyStatus` (`+WorkWrites.swift:328-330`). *Fix:* check the closed state after the call's own status.
18. **An add that changes nothing still goes in the write journal.** Confirmed, minor. `MCPNotebookTools+WorkCheckIns.swift:116-157`. *Fix:* `markNothingWritten()`.
19. **A departed child's linked copy still gets the check-in.** Plausible, minor. `MCPNotebookTools+WorkCheckIns.swift:138-160,231-232`. *Fix:* skip copies whose owner isn't enrolled and name them in the reply.

## Restock and order requests

20. **Merging two open needs for one staple loses what the office was asked for.** Plausible. `Supplies/Services/RestockService+Needs.swift:277-283` copies the request fields but not quantity, notes, title or link, so "Asked for" can show 1 when 6 were ordered. *Fix:* copy them too, or always keep the asked-for copy.
21. **The Assistant's "We need…" ignores the quantity when the name matches a staple.** Confirmed. `Daybook Assistant/Restock/AssistantRestockModel.swift:315-318`. *Fix:* set the quantity on the staple's open need while it hasn't been asked for.
22. **Links the Assistant pastes never get a title,** so the email reads "1. amazon.com — https://…". Confirmed. `AssistantRestockModel.swift:321-330`. *Fix:* fill missing titles on the notebook when Restock or the draft opens.
23. **The need editor's Link field saves any text as the link.** Confirmed. `Orders/Services/OrderService.swift:151-152`. Pasted share text is saved whole; Open Link does nothing, and a non-web address would be opened. *Fix:* pull out the first web link, or refuse with the note `StapleEditSheet` uses.
24. **Email addresses aren't checked, and spaces don't separate them.** Confirmed, minor. `Attendance/Email/AttendanceEmailReport.swift:268-275`. *Fix:* split on whitespace too, keep only address-shaped entries, say which were dropped.
25. **The iPhone "no mail account" message can never appear.** Confirmed, minor. `Orders/Views/OrderRequestDraftSheet.swift:302-315` opens the mail link without checking whether it opened, then always asks "Did the email send?". *Fix:* use the completion handler.
26. **An office-run save failure isn't shown on the office run.** Confirmed, minor. `Daybook Assistant/Restock/AssistantOfficeRunView.swift`; "We need…" also closes when its save failed. *Fix:* show the error there and keep the sheet open.
