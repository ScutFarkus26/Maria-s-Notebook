## Launch cleanup and lessons

1. **The same-name lesson merge and same-title track merge undo the ID cleanup's restore guard, and with one id on both sides they delete every track step of the lesson.** Plausible trigger (needs a Replace restore arriving), confirmed path, high. `Services/Migrations/DataCleanupService+LessonNameMerge.swift:42-60, 102-124, 188-191, 355-372`, `+TrackTitleMerge.swift:34-45, 83-105, 147-163`, called right after the ID pass at `+Deduplication.swift:304-308, 342-346`. The ID pass defers a same-id pair whose `createdAt` ties while a restore may still be arriving (`DedupSyncState.tieStillSettling`, `:150-157`). Lessons have no `createdAt`, so every same-id lesson pair ties; restored tracks keep their `createdAt`, so they tie too. The name merge then groups the two copies (same id, same name), keeps the older CloudKit record — the outgoing one — and deletes the restored one. When the restoring device's own delete of the old record arrives, the lesson is gone everywhere. And because both copies share an id, `repointLessonReferences(from: id, to: id)` runs `repointTrackSteps` with `old == new`: the "moved" steps and the "already stepping" tracks are the same set, so **every track step for that lesson is deleted**, and children lose track progress. *Fix:* leave out of both merges any group in which two members share an id (the ID pass owns those); apply `tieStillSettling` to the whole group before folding; return early when `old == new`.
2. **Renaming or moving a lesson into a sub-area that already has one by that name merges it away at the next launch.** Confirmed, high. The merge treats any two lessons with one folded area, sub-area and name as one lesson filed twice (`LessonNameMerge.swift:102-124`), but only `LessonRepository.createLesson` refuses such a pair (`Repositories/LessonRepository.swift:134-140`). The lesson editor's Save (`Lessons/Detail/LessonDetailView+Actions.swift:15-28, 75-79`), dragging a lesson to another sub-area (`Lessons/Library/LessonsRootViewReordering.swift:119-131`) and MCP `update_lesson` with `area`/`sub_area` (`MCPNotebookTools+CurriculumWrites.swift:250-273`; its twin check at `:199-205` runs only when `name` is passed) make one with no check. Drag "Introduction" from Decimals into Fractions, which has one: at the next launch one is deleted, its write-up survives only where the other's is empty, and a child's marks and year-plan entries for the two are folded into one. `existingLesson(…, excluding:)` exists for exactly this and has no callers. *Fix:* run it in all three paths and refuse with Add Lesson's wording.
3. **The lesson merge drops Going Out curriculum links and story match reasons.** Confirmed, low. `LessonNameMerge.swift:195-246` misses `CDGoingOut.curriculumLinkIDs` and the keys of `CDStory.relatedLessonReasonsJSON`. *Fix:* repoint both.
4. **Bulk Add Lessons: a retry after a failed save says every lesson is "already filed".** Confirmed path, low. `Lessons/BulkLessonsEntryView.swift:362-369`, `BulkLessonInsertion.swift:62-86`: the unsaved inserts stay in the context, so the retry finds each lesson's own unsaved copy, shows "Some Lessons Were Already Filed" and closes; the lessons are written by some later save or lost on quit. Add Lesson does the same (`AddLessonView.swift:256-259`). *Fix:* roll the inserts back on a failed save (`ContextMutationTransaction`).
