## Sync status and sharing

1. **A notebook launched by Siri never learns that sync stopped, so Siri's marks still go into the share.** Confirmed path, high. `Services/Sync/CloudKitSyncStatusService+EarlyEvents.swift:85-92`, `Sharing/SharedStoreOrphanGuard.swift:130-136,242-245`, `Siri/SiriHost.swift:87`. Before `configure`, `receive` only follows the account hold; every other finished event is buffered, and only `handleCloudKitEvent` sets the stopped flag. A background Siri launch has no window, so `configure` never runs. If setup failed for any reason other than the account (a server refusal, 134406, a store migrated by another process), "Maya is here" goes `siriDidSave` → `flush` → `share(_:to:)` on a store whose setup failed — the call that can raise an exception Swift can't catch. Windowed launches have the same gap for the moments before `configure`. *Fix:* in `receive`, track the stopped flag for failed events as they arrive (keyed by store, as the account hold is); marks are dated, so marking again at `configure` is harmless.
2. **A setup that fails for network reasons holds nothing.** Plausible, medium. `+StoreHealth.swift:46`, `CloudKitStoreHealth.swift`, `+AccountReadiness.swift:69-71`. A network, busy-zone, throttle or service-down failure isn't "dead" and isn't "no account", so neither the stopped flag nor the hold is set; the next save's pass calls `share(_:to:)` on a store that never set up — the condition 10-09 #2 fixed for a missing account. *Fix:* put transient setup failures into the same "set up, then sync" hold.
3. **The fix for 10-09 #3 switched off the protection for the first share a device ever sees.** Confirmed that the protection is gone, plausible harm; medium. `Sharing/SharedStoreOrphanGuard+WaitingList.swift:134-141`. "No zone noted" now means "older build, forget nothing", but a new-build device that has never seen a pin also has no key — the iPad in the minutes before the Mac's Set Up reaches it. It then files records the Mac is attaching at the same moment. Dormant today (one share exists, every device holds the pin); returns on any set-up from scratch. The test was changed to pre-set a zone, so nothing covers this case. *Fix:* record a "pins tracked since" marker when this build finds no pin; a first pin newer than the marker forgets as before.
4. **Opening the Mac right after login probably still pauses sharing until reopen.** Plausible, medium. `+AccountReadiness.swift:102-114`. After a 134400 the code asks `accountStatus()` once, at once; if login still reads `.noAccount`, it latches `shareFilingPausedUntilReopen`, the "Mac open all day never shares" case 10-09 meant to fix (it's the Tide device check). `.untilICloudReady` also has no way out if Core Data never retries setup. *Fix:* ask again after the account-changed notice or a minute, and latch only if still no account and the store hasn't set up since.
5. **The import that ends the pin wait doesn't wake the filing step.** Plausible, low (a delay). `SharedStoreOrphanGuard.swift:95-101,189`, `+EventHandlers.swift:284-293`. The remote-change notice usually comes before the import's end event, so the pass it starts still sees the wait, and nothing retries after the watermark is written (same for clearing a stop). After the roll-out every device enters this wait once, so a quiet Mac's marks can sit outside the share past the 9:00 email. *Fix:* when a private-store import finishes with `pinSeenAt` set, or a stop clears, call `flushPendingIfPossible()`.
6. **An attach under way doesn't stop when sync stops or a hold starts.** Plausible, low–medium. `Sharing/ClassroomShareAttach.swift:161-196`. The stop check runs once per pass, then up to 16 chunks of `share(_:to:)` go out. *Fix:* check before each chunk.
7. **The "until reopened" message is wrong.** Confirmed, low. `+AccountReadiness.swift:47-48`, `ClassroomShareError.iCloudNotReadyAtLaunch`. It's shown only when no account is signed in but says iCloud "wasn't ready"; reopening without signing in brings it back. *Fix:* "No iCloud account was signed in when the notebook opened. Sign in to iCloud, then quit and reopen the notebook."
8. **Switching Apple Accounts clears a stop an attach found.** Plausible, low. `+StoreHealth.swift:120`. *Fix:* keep attach-found stops across `resetForNewAccount`.
9. **"Your name" can say "Saved on this device" for a name that's then dropped.** Confirmed path, rare; low. `Sharing/ClassroomNames.swift:132-139`, `ClassroomYourNameCard.swift:97-106`. An account change mid-lookup returns `.waiting`, then `forgetWaitingName()` drops it; the card still shows it and won't save it again. *Fix:* post a notice from `forgetWaitingName` that the card reloads on.

## What runs through all of it

- **Saves that never happen.** The view context has autosave off (since the SwiftData move), and several old screens still change records without saving: a Quick Note (#1), the Mac lesson window and the Parsha lesson pages (#38), AI-plan Apply (#78), work steps and sample works (#49), a todo's date chip (#24), Remove Unused tags (#30). The change sits in memory until some unrelated save, and is lost if the app quits first or a failed save rolls the context back. A sweep for writes with no save after them would catch the rest.
- **Paths that skip the one service.** Ticking a todo outside Today (#17), marking a check-in done on the work page (#51), the checklist's Mastered (#41) — each writes the field directly and misses what the service does (next repeat, linked todos, touch dates, reusing closed work).
- **`Dictionary(uniqueKeysWithValues:)` over rows that can be duplicated by sync** traps on a duplicate: the dashboard's sequence loader, Presentations' days-since and blocking engine, the story matcher (#68). 28 files use it; the rest are worth a look.
- **First names alone** where the two Ettys and two Sarahs need "Maya S": New Todo, the work page header, Book Club leaders and rosters, chat (#27, #58, #85, #90).
- **Children who left still included**: the work page's cohort lists, Today's cache, project check-ins, todo templates, Book Club edits (#55, #86, #89, #28, #73).

## Notes and Quick Capture

1. **A Quick Note is never saved.** Confirmed, high. `Notes/QuickCapture/QuickNoteViewModel.swift:239-275`. `saveNote` makes the note and shows "Note saved" but never saves or posts `.noteDidSave`; nothing else in the app saves on background. Lock the phone, iOS ends the app, the note is gone and never reached iCloud. *Fix:* save through `SaveCoordinator`, sync student links (#2), post `.noteDidSave`, toast only on success.
2. **Notes about two or more children show on none of their Notes tabs.** Confirmed, high. `QuickNoteViewModel.swift:264-273`, `Notes/Editor/NoteEditorSaveLogic.swift:51-86`. Neither calls `syncStudentLinks` (the other 11 writers do), and `StudentNotesViewModel.fetchGeneralNotes` finds a multi-child note only by links. Re-scoping in the editor leaves old links. Group check-in notes have the same gap (`Models/CDUnifiedNotes+Helpers.swift:46-53,131-138`). *Fix:* sync links in all three; a one-off repair for `.students` notes with no links.
3. **Ordinary words are read as initials and tag the wrong children.** Confirmed, high. `StudentTagger.swift:137-155,292-299`, `StudentPatternMatchers.swift:45-55`. The last pass matches two-letter initials case-insensitively, so "is", "to", "in", "at", "me" tag the child with those initials; "a.m.", "p.m.", "e.g.", "i.e." count as dotted initials; "Maya S a bead frame" picks an S.A. child. Quick Note adds every match, and removing the chip doesn't stick (the next keystroke re-adds it). *Fix:* capitals or periods only in the last pass; skip those abbreviations; remember chips she removed.
4. **Auto-tidy deletes the word after a name.** Confirmed, high. `StudentTagger+Replacements.swift:200-238`. "gave Leo a pencil" (Leo's last name starts with A) becomes "gave Leo pencil"; with two Leos, "gave Leo A pencil" and Leo A tagged as certain. Same for "Sarah I think". *Fix:* a lone "a" or "I" is never a last initial; never replace with text that drops what she typed.
5. **Expand Initials can crash or corrupt the note.** Path confirmed, needs an emoji; high. `Notes/Editor/NoteEditorHelpers.swift:286-313` applies UTF-16 ranges as character counts. "Great job 👍 JD" → wrong letters replaced, or a read past the end. "PE", "OK", "TV" expand into names. *Fix:* `Range(match.range, in:)`, replace from the end; require clear initials.
6. **Format Names garbles names.** Confirmed, medium. `StudentTagger+Replacements.swift:10-59`. "Maya Smith" → "Maya S S"; with two Sarahs, "Sarah" → "Sarah K M"; one-of-a-kind names are tidied back 300 ms later. The menu says "(Maria G.)" with a period. *Fix:* one pass over the original text; skip text already in short-name form.
7. **Accented names break the matcher's lookups.** Confirmed when such names exist, medium. `StudentTagger.swift:309-324`, `StudentTagger+Replacements.swift:81,120` look up folded keys with accents kept: "Zoë S" tags both Zoës. *Fix:* `folded()` on both sides.
8. **Notes on a shared work row show only on the owner's Notes tab.** Confirmed, medium. `Students/Notes/StudentNotesViewModel.swift:147-163`. *Fix:* also fetch work where she's a participant.
9. **The Notes tab dates notes by last edit.** Confirmed, medium. `StudentNotesViewModel.swift:133,169,212` use `updatedAt`; pinning or flagging re-dates a note to today and moves it into this year, and backdated Quick Notes show today. *Fix:* `createdAt`.
10. **"Legacyfield: system" and whole-class clutter on every Notes tab.** Confirmed, medium. `CDUnifiedNotes+Helpers.swift:77-86,120-152`, `StudentNoteRowView.swift:118-130`. Old note-field notes carry an internal reporter label; project-session notes are scoped to the whole class; check-in notes read "General Note". *Fix:* treat `legacyField` as the guide's note; scope sessions to their children.
11. **Writing Help drafts from the wrong notes, and Anonymize still sends names.** Confirmed, medium. `Students/Notes/StudentNotesTab.swift:21-30`, `AppleIntelligenceSheet.swift:61,194,265-276`. Misses group notes, includes every year's whole-class notes; Anonymize hides only the "Student:" line, not names in the bodies; toggling it or picking a draft overwrites her edits. *Fix:* reuse the Notes tab's fetch plus the school year; replace roster names in bodies.
12. **Suggest Tags › Apply replaces the chosen children with the AI's guess.** Confirmed, medium. `NoteEditorAISuggestion.swift:89-98`. "Sarah" picks the first Sarah. *Fix:* merge, skip ambiguous names.
13. **Opening a note in the editor adds the children it mentions.** Plausible, medium. `UnifiedNoteEditor.swift:152-157`. *Fix:* skip detection for the note's existing text.
14. **Note sheets throw away typed text on a swipe or Cancel.** Confirmed on iOS, medium. `QuickNoteSheet.swift:270,374`, `NoteEditSheet.swift`, `UnifiedNoteEditor.swift:204`. *Fix:* block dismiss and ask while there's unsaved text.
15. **Nicknames that are ordinary words get rewritten** ("a sunny day" → "a Alexandra day"). Plausible, medium. `StudentTagger+Replacements.swift:127-134`. *Fix:* tag nickname matches, don't rewrite them.
16. **Smaller:** "a"/"I"/"and"/"was" suggest children (`String+FuzzyMatch.swift:36-45`); the cursor likely jumps on auto-tidy; withdrawn children's chips are blank or can't be removed (`ObservationsDataLoader.swift:139`); the editor ignores a failed save and closes, and deletes the old photo before saving (`NoteEditorSaveLogic.swift:27,53-61`); the Notes-tab quick bar clears text on a failed save; batch delete counts meeting and attendance rows it won't touch; removed or cancelled photos stay on disk.
