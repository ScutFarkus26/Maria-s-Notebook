## Apple guidance

Checked 2026-10-17 against Xcode 27.0 (27A266a; iOS/macOS 27.0 SDKs). Targets: notebook iOS 27.0 / macOS 27.0, Assistant iOS 18.0. Xcode 27.1 is released and 27.2 is in beta; their notes touch none of these APIs, so no update first. Doc pages modified 2026-08-06 … 10-16.

- **A1. Upright thumbnails (Ph #21).** `kCGImageSourceCreateThumbnailWithTransform: true` applies the EXIF orientation (iOS 4 / macOS 10.4); `kCGImageSourceThumbnailMaxPixelSize` then bounds the long side after rotation (tested on the macOS 27 SDK with an orientation-6 JPEG). `PhotoImageIO.swift:145` already sets it; `PhotoStorageService`'s two paths don't. ([key](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform))
- **A2. Opening a file on iPhone and iPad (Al #22).** `UIApplication.open` with a `file://` URL isn't documented to work and in practice doesn't (forum-grade). Use SwiftUI `.quickLookPreview(_ item: Binding<URL?>)` (iOS 14 / macOS 11; Quick Look sets the binding to nil on dismissal), or `ShareLink` (iOS 16) for "open in another app". Pass `.absoluteURL` to anything URL-based (iOS 27 bug with relative URLs, FB24935354). `canOpenURL` is deprecated in iOS 27. ([quickLookPreview](https://developer.apple.com/documentation/swiftui/view/quicklookpreview(_:)))
- **A3. Handoff and external events (Sh #32, #33).** Routing, per the scene doc: an open scene whose view declares `handlesExternalEvents(preferring:allowing:)` for the event wins; with no declaration anywhere, SwiftUI opens a **new** instance of the first scene without the scene modifier — every Handoff opens another main window. Fix: `.handlesExternalEvents(preferring: ["*"], allowing: ["*"])` on the main window's root content (iOS 14 / macOS 11). Whether an activity that arrives before an `onContinueUserActivity` view appears is delivered later is **undocumented**: attach the handler at the scene's root content, which always exists. ([handlesExternalEvents](https://developer.apple.com/documentation/swiftui/scene/handlesexternalevents(matching:)), [onContinueUserActivity](https://developer.apple.com/documentation/swiftui/view/oncontinueuseractivity(_:perform:)))
- **A4. Trash and coordinated moves in iCloud Drive (Al #23, #24).** `FileManager.trashItem(at:resultingItemURL:)` (iOS 11 / macOS 10.8) has no documented behavior inside a ubiquity container. So for D3: coordinate a `trashItem`; if it throws, **delete nothing** and say "Couldn't move the album to the Trash, so it's still in iCloud." (a device check covers iPhone and iPad). A plain delete there is permanent. For an atomic copy, coordinate `.forMoving` on the temp source and `.forReplacing` on the destination — `UbiquitousFile.coordinatedMove` already does. Never nest coordinator calls inside an accessor block. ([trashItem](https://developer.apple.com/documentation/foundation/filemanager/trashitem(at:resultingitemurl:)), `NSFileCoordinator.h`)
- **A5. Reminder identity (Cal #13).** `calendarItemIdentifier` is device-local and "a full sync will lose" it; `calendarItemExternalIdentifier` is the server's id meant for the same reminder across devices, nil only for unsaved items — but on a **local** list it equals the local id, and on **Exchange** it differs per device. Duplicates are possible (`calendarItems(withExternalIdentifier:)` returns an array). `EKCalendar` has no external id: identify a list by its source (account) plus title, as Apple advises caching other properties. So: key by external id, fall back to the local id when the external one is missing or equals the local one; accept that Exchange reminders on two devices may still make two rows (note it under Decided during the run). ([calendarItemExternalIdentifier](https://developer.apple.com/documentation/eventkit/ekcalendaritem/calendaritemexternalidentifier))
- **A6. Siri entity matching (At #4).** `EntityStringQuery.entities(matching:)` (iOS 16 / macOS 13) has no documented fuzzy-matching guidance, and it is **unconfirmed** that one result skips Siri's disambiguation — so never return a lone guess. Inside `perform()`, `requestDisambiguation(among:dialog:)` and `requestConfirmation(for:dialog:)` exist if a near-miss must be offered. WWDC26 session 240 prefers `IndexedEntity`; not adopted here (out of scope). ([EntityStringQuery](https://developer.apple.com/documentation/appintents/entitystringquery))
- **A7. Foundation Models errors and timeouts (AI #9, #16).** `GenerationOptions` has **no timeout**; build a race that cancels the request task after the caller's interval. iOS 27's `LanguageModelError` (`contextSizeExceeded`, `guardrailViolation`, `rateLimited`, `refusal`, `timeout`) replaces the deprecated `GenerationError` cases. A failing tool arrives as `LanguageModelSession.ToolCallError`. After a throw, `session.transcriptErrorHandlingPolicy` (`.revertTranscript` / `.preserveTranscript`) decides what the transcript keeps; its default is undocumented, so set it explicitly and record a write's side effect in the tool itself (`ChatToolContext`), not by reading the transcript. ([LanguageModelError](https://developer.apple.com/documentation/foundationmodels/languagemodelerror), [TranscriptErrorHandlingPolicy](https://developer.apple.com/documentation/foundationmodels/transcripterrorhandlingpolicy))
- **A8. Warning before losing typed text (Sh #31).** `dismissalConfirmationDialog(_:shouldPresent:actions:)` (iOS 27 / macOS 15) covers only its own window; macOS asks on programmatic dismissal too. No SwiftUI API warns about other windows, so #31 needs the app's own "editors open" registration, and an ordinary `.confirmationDialog` before switching. HIG (alerts, sheets): offer to discard or keep editing. ([dismissalConfirmationDialog](https://developer.apple.com/documentation/swiftui/view/dismissalconfirmationdialog(_:shouldpresent:actions:)))

Seen in passing, not a finding and not changed here: `UbiquitousFile.coordinatedReplace` uses `.forReplacing` for a rename-into-place that the header says it isn't for.
