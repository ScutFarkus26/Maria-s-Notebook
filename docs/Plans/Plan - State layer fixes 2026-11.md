## Apple guidance
Checked 2026-11-22 by the review session against the installed Xcode 27.2 SDK (Swift 6.4.2) and developer.apple.com; not checked again for this plan.
- **`@Observable` skips equal values.** The macro's setter calls `shouldNotifyObservers` (`Observation.swiftinterface:25`): setting a property to a value equal to the old one (`!=` for Equatable values, `!==` for plain class references, element by element for arrays) stores it and tells no one. Apple documents none of this, so B4's and B5's tests pin it. A `swiftc` test on this toolchain confirmed it: the same `NSObject`s re-assigned sent 0 notices.
- **`withMutation(keyPath:)` always notifies; `access(keyPath:)` registers a read.** Both are public on the generated type. B4 uses the first; B6 uses both for a value kept outside the object.
- **`@ObservationIgnored`** on stored properties no view reads (task handles, hashes, caches, contexts) keeps them out of tracking. A property a view reads through a computed property must stay tracked.
- **`@Bindable`** is for making a `$binding` from an observable object; a view that only reads takes a plain `let` or `var`.
- **`@Environment(SomeType.self)`** with a non-optional type is a fatal error when no ancestor supplied the object (B1).
- **Not used in this run:** `isolated deinit` (unsettled under `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`), `Observations { }`, the typed notification messages, lazy `@State` defaults (the review's items 11, 18, 19).
