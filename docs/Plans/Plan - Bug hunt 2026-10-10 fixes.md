## Apple guidance

Checked 2026-10-10 against Xcode 27.0 (27A266a, Swift 6.4, iOS/macOS 27.0 SDKs). Xcode 27.1 RC and 27.2 beta 2 exist; their release notes touch none of these topics, so no need to update first. Most doc pages last modified Aug 14 or Sep 11, 2026.

- **G1. Calendar occurrence keys (agent F).** `calendarItemExternalIdentifier` is the server's ID, meant for "the same event across multiple devices", and is the same for every occurrence of a series; `occurrenceDate` is the original scheduled date (unchanged when one occurrence is moved). `eventIdentifier` "is likely to change if the calendar changes" and the SDK header adds it can change "due to a sync operation"; `calendarItemIdentifier` and `calendarIdentifier` are local. **Key rows by `calendarItemExternalIdentifier` + `occurrenceDate`** (all-day events normalized to day components, since they come back in the default time zone); keep `eventIdentifier` only as a per-device cache. Caveats: duplicates are possible (an ICS imported twice, shared calendar plus invitation; disambiguate by calendar title + source), and Exchange gives a different value on iOS and macOS (accepted: worst case those events show twice, as today). `requestAccessToEntityType:` is deprecated; use `requestFullAccessToEvents`. ([calendarItemExternalIdentifier](https://developer.apple.com/documentation/eventkit/ekcalendaritem/calendaritemexternalidentifier), [occurrenceDate](https://developer.apple.com/documentation/eventkit/ekevent/occurrencedate))
- **G2. PDF colors (agent G).** Apple documents nothing about how `UIGraphicsPDFRenderer` resolves dynamic colors, and `UITraitCollection.current` is "undefined" outside UIKit's callbacks. So draw with fixed colors, or wrap the drawing in `UITraitCollection(userInterfaceStyle: .light).performAsCurrent { }` ("the preferred way"); on macOS `NSAppearance(named: .aqua)?.performAsCurrentDrawingAppearance { }` (`NSAppearance.currentAppearance` is deprecated). The test renders under a dark trait and checks the text color. ([performAsCurrent](https://developer.apple.com/documentation/uikit/uitraitcollection/performascurrent(_:)), [performAsCurrentDrawingAppearance](https://developer.apple.com/documentation/appkit/nsappearance/performascurrentdrawingappearance(_:)))
- **G3. Pagination (agent G).** Multi-page text needs TextKit 1: `NSLayoutManager` with one `NSTextContainer` per page (`glyphRange(for:)`, `usedRect(for:)`). TextKit 2's `NSTextLayoutManager` has a single container in this SDK. `NSLayoutManager` is "legacy", not deprecated. ([TextKit](https://developer.apple.com/documentation/uikit/textkit))
- **G4. Dictation closures (agent J2b).** Under main-actor default isolation, plain closures passed to `SFSpeechRecognizer.requestAuthorization`, `installTap(onBus:…)` and `recognitionTask(with:resultHandler:)` compile as MainActor with a runtime isolation check (SE-0423) that halts when Apple calls them off the main thread, which both headers say can happen. Verified with the compiler: a `{ @Sendable … }` closure, or one built inside a `nonisolated func`, has no check. **Fix with `@Sendable` closures that hop to the main actor for UI state.** `installTap` is deprecated in 27.0 for `installAudioTap(onBus:bufferSize:format:tapProvider:)`, but its `AVReadOnlyAudioPCMBuffer` can't be fed to `SFSpeechAudioBufferRecognitionRequest`, so keep `installTap` (its deprecation warning predates this plan and stays). `SpeechAnalyzer` (iOS 26+) is Apple's newer path; moving to it is out of scope. On a normal stop, ignore `kLSRErrorDomain` 301 ("Request was canceled") and `kAFAssistantErrorDomain` 1110 ("no speech"). ([installAudioTap](https://developer.apple.com/documentation/avfaudio/avaudionode/installaudiotap(onbus:buffersize:format:tapprovider:)), [SpeechAnalyzer](https://developer.apple.com/documentation/speech/speechanalyzer))
- **G5. Sheets and identity (agents F, H, E1).** Docs and HIG don't promise a sheet's toolbar shows without a navigation container, so the Topics sheet gets a `NavigationStack`; the HIG puts Cancel leading and Done/Save trailing, and says to confirm before discarding unsaved changes. `interactiveDismissDisabled` blocks only the drag and tap-outside. `.id(_:)` resets the view's state when the value changes; `.task(id:)` cancels and restarts on change. In the 27.0 SDK `@State` is a macro: an initial value plus an `init` assignment no longer compiles. ([id](https://developer.apple.com/documentation/swiftui/view/id(_:)), [sheets HIG](https://developer.apple.com/design/human-interface-guidelines/sheets))
- **G6. CloudKit events and account status (agent A).** The 27.0 typed `EventChangedMessage` is "posted … on the CloudKit private serial queue"; treat events as off-main. Apple says nothing about delivery in an App Intent launch with no scene, so the fix mustn't depend on a window. `.temporarilyUnavailable` means signed in but not ready: don't enqueue, wait for `CKAccountChanged`. Apple doesn't say whether `.noAccount` can be transient right after login, so re-check on `CKAccountChanged` (posted on an arbitrary queue; needs a `CKContainer` instance) and on a timer, as Decisions says. TN3164 documents automatic retry only for throttles, not setup failures. ([EventChangedMessage](https://developer.apple.com/documentation/coredata/nspersistentcloudkitcontainer/eventchangedmessage), [TN3164](https://developer.apple.com/documentation/technotes/tn3164-debugging-the-synchronization-of-nspersistentcloudkitcontainer))
- **G7. Date parsing (agent I).** `DateFormatter`'s `twoDigitStartDate` defaults to 31 Dec 1949 (`yy`: 49 → 2049, 50 → 1950); `yyyy` reads "15" as year 15 — the CSV bug. `Date.ParseStrategy` has different defaults (`isLenient: true`, two-digit start 1970), so pass both explicitly if used. Apple suggests `FormatStyle`/`VerbatimFormatStyle` in Swift; `DateFormatter` isn't deprecated. **Try `yy` formats before `yyyy`, non-lenient, and refuse years before 1900.** ([twoDigitStartDate](https://developer.apple.com/documentation/foundation/dateformatter/twodigitstartdate))
- **G8. Regex ranges (agent E2).** `NSRegularExpression` works in UTF-16 `NSRange`: search with `NSRange(s.startIndex..., in: s)`, never `s.count`, and convert matches back with `Range(_:in:)` (nil for no match). Swift `Regex` works in `String.Index` directly and is fine for new tagger code; `NSRegularExpression` isn't deprecated.
