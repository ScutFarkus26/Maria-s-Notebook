**What this plan changes from the first one, and that Danny confirmed**

With Tide the list, Reminders is a third list for the same errands. Danny confirmed the reversal on 2026-11-03.

**Settled here, with why**
- **Tide is the to-do list.** The notebook keeps what only the notebook can make: automatic work check-ins ("Check in with Maya on …", which the first plan already kept out of Tide), follow-ups owed to a child (`list_open_follow_ups`), and Tide to-dos that name a child, shown on her page as today. Everything a person types as a to-do goes to Tide, as Phase 10 of the first plan already arranged. So the notebook's own Todos screen shrinks to Check-ins, From Tide and Done, and subtasks, todo templates, priorities, someday, tags and the todo export go. **The ~13 open hand-typed to-dos** go across through the existing Tide sharing run on the Mac before the list is slimmed; a "Not yet in Tide" list shows any still here and disappears when it's empty, so nothing open is ever hidden.
- **Retiring an entity means a tombstone, not a model edit.** CloudKit Production can't drop a record type and older builds may still write it, so `Reminder`, `TodoSubtask`, `TodoTemplate`, `ClassroomJob`, `JobAssignment`, `PracticeSession` and `NoteTemplate` join `CoreDataStack.dormantTombstoneEntities` (`AppCore/Persistence/CoreDataStack+Model.swift:214`), their classes go, their class name in the model is blanked (Apple guidance), and the orphan cleanup leaves their rows alone. The eight existing tombstones show the pattern. No schema-version bump for a tombstone. (Phase 2's one new attribute is the plan's only schema bump.) `Phase8PreTests` gains a check that no `NSFetchRequest(entityName:)` names a tombstone, because a string fetch still compiles after the class is gone.
- **A backup still restores old files.** The backup stops *writing* a retired type and the importer treats a retired type's section as "known, skipped", so a 2026 backup restores without a warning about reminders it no longer has anywhere to put. Backups written before this plan keep their reminders; nothing is destroyed on disk. **One format bump, one golden**: Phases 1, 2 and 4 each remove their rows and re-record the golden in their own worktree to pass their tests, but leave `BackupWriter.formatVersion` (44 today) alone; Phase 5 does the single bump to 45 and the one golden re-record after merging them. Phase 7 keeps the skipped list as one table column.
- **Empty features are made cheap, not deleted.** Cheap means: no Claude tool until the feature has a record (Phase 6 removes them; adding one back is a half-hour job), the sidebar hides an empty Classroom row until its first record (the group already starts collapsed), and the code stays. Classroom Jobs is the exception: its folder is two entity files, it has no screen, and its only readers are two Claude tools and the monthly-report context builder, so it is retired outright.
- **Practice into check-ins, how.** `WorkCheckIn` gets an optional `durationMinutes` and the "noticed" signals (`madeBreakthrough`, `helpedPeer`, …) go on the check-in's note as its existing tags. **The copy runs on every launch and after every restore**, keyed by the session's id in the check-in note, so a Replace restore of an older backup (which clears `WorkCheckIn` and skips `PracticeSession`) brings the copied check-ins back on the next launch. Notes linked to a session (`Note.practiceSession`) are re-linked to the new check-in (`Note.workCheckIn`, which already exists). The entity becomes a tombstone once the copy has run on every device, which the tombstone itself doesn't require: rows stay. The practice stats on Work detail (`Work/Detail/PracticeStats.swift`) read check-ins instead.
- **Claude tools consolidate by subject, not by verb.** The seven `student_*` reads become one `student_record` with `sections:` (attendance, curriculum_map, meetings, observations, presentation_history, tracks, work). `list_lessons_by_area` folds into `find_lessons`; `list_orders`/`add_order_items`/`update_order_items` fold into `list_supplies`/`mark_supplies` with a stage; `set_timetable`/`change_schedule_day`/`weekly_schedules` stay (Schedules is live). Retired with their features: `list_reminders`, `classroom_jobs`, `assign_job`, `practice_sessions`, `list_going_outs`, `update_going_out`, `list_procedures`, `book_club`, `list_stories`, `add_project_session`, `project_detail`, `update_project` (Projects are dormant; `list_projects` stays so Claude can say so). Target: about 60. Every retired name is listed in `docs/Technical notes/MCP_SERVER.md` under "Retired", and the server answers a retired name with a plain "that moved into …" message rather than an unknown-tool error. `MCPToolRegistryTests` (CLAUDE.md requires a line in it per tool) is updated and run by every phase that adds, changes or removes a tool.

## Apple guidance

Checked 2026-11-03 by an `sdk-verifier` pass against the installed Xcode 27.2 (27B52) SDKs (iOS, macOS 27.2), Apple's documentation JSON, the HIG and the 27.0–27.3 release notes. 27.2 is the newest released Xcode; the 27.3 betas change nothing here. Targets: notebook iOS 27 / macOS 27, Assistant iOS 18 (untouched by this plan).

- **Retiring an entity (Phases 1, 2, 4).** Apple: "You can't delete a record type or modify any existing attributes after you promote a development schema to production"; production types "exist for all time" ([Creating a Core Data Model for CloudKit](https://developer.apple.com/documentation/coredata/creating-a-core-data-model-for-cloudkit), 2026-10-08; [Deploying an iCloud Container's Schema](https://developer.apple.com/documentation/cloudkit/deploying-an-icloud-container-s-schema), 2026-08-14). Keeping the entity with no code is this repo's practice (eight tombstones already), not an Apple term. Removing the `NSManagedObject` subclass changes no version hash (the hash uses only what affects persistence: [versionHash](https://developer.apple.com/documentation/coredata/nsentitydescription/versionhash)), so there is no migration; **blank the entity's class name in the model** so it falls back to `NSManagedObject` rather than naming a class that no longer exists (undocumented case). Records of a retired type still arrive from CloudKit and sit in the store unread; the existing tombstones show that works.
- **Turning Reminders off (Phase 1).** There is no revoke API (the EventKit headers have none). On `EKEventStoreChanged` "consider all instances invalid… release them", and "releasing an event store instance before other EventKit objects may result in an error" ([Accessing the event store](https://developer.apple.com/documentation/eventkit/accessing-the-event-store), 2026-10-08): stop observing, release reminders and calendars, release the store last. **Order of removal: take out the code that requests Reminders access first, then the two usage strings** (`NSRemindersFullAccessUsageDescription`, `NSRemindersUsageDescription`; iOS 17 / macOS 14). iOS 17+ denies silently when the key is missing; Apple documents nothing for macOS, so the code must be gone before the key is. There is no separate Reminders entitlement on macOS: `com.apple.security.personal-information.calendars` covers both and stays (events still show on Today).
- **FoundationModels (Phase 3).** From `FoundationModels.swiftinterface` 27.2: `SystemLanguageModel.default`, `init(useCase: UseCase = .general, guardrails:)` (iOS/macOS 26; use cases `.general` and `.contentTagging` only), availability `.available` / `.unavailable(.deviceNotEligible | .appleIntelligenceNotEnabled | .modelNotReady)`. **Private Cloud Compute is its own public type**, `PrivateCloudComputeLanguageModel` (iOS/macOS 27), with its own `availability`, `isAvailable` and `quotaUsage`; both conform to `LanguageModel` and `LanguageModelSession(model:)` takes either. Nothing reports where a session runs, so a merged client must remember which model it built. Without the managed entitlement `com.apple.developer.private-cloud-compute`, PCC reports available and then "crashes with a fatal error" on the first prompt ([Detecting available models](https://developer.apple.com/documentation/foundationmodels/detecting-available-apple-foundation-models), 2026-10-25); the app's entitlements file carries that key only in a comment today. Apple's advice: start on device, fall back to it when PCC fails ([PCC article](https://developer.apple.com/documentation/foundationmodels/adding-server-side-intelligence-with-private-cloud-compute), 2026-10-08). So Phase 3 merges the two *wrapper classes* into one `FoundationModelClient` that holds either model, and the on-device/PCC choice stays, gated as now on the entitlement being present. Keep `#if ENABLE_FOUNDATION_MODELS && canImport(FoundationModels)`.
- **Settings (Phase 3).** [HIG Settings](https://developer.apple.com/design/human-interface-guidelines/settings) (2026-08-06): minimize the number of settings, a fixed set of panes, the window title follows the pane, restore the last pane. Nothing on a row count; [HIG Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars) (2026-08-20) allows two levels. No Apple page covers a retired raw value in a persisted selection, so the alias pattern stands.
- **One optional attribute (Phase 2).** "Addition of an attribute" is inferred automatically ([Migrating your data model automatically](https://developer.apple.com/documentation/coredata/migrating-your-data-model-automatically), 2026-10-08). This repo edits its one model version in place and has shipped schemas 19–22 that way with the newer-build guard in `CoreDataStack+SchemaVersion.swift`; follow that precedent, not a new model version. Order: edit the model → one Debug run with `initializeCloudKitSchema(options: [])` against Development (the scheme's `-InitializeCloudKitSchema`, unchecked afterwards) → check in the CloudKit Console → Deploy Schema Changes to Production (Danny) → ship.
- **Hiding sidebar rows (Phase 2).** iOS/iPadOS 27.0 notes: "a TabView enforces that its selection is set to a visible tab… might crash when its selection is set to a hidden or otherwise unavailable tab (164516837)". The macOS notes have no equivalent and `NavigationSplitView` selection is undocumented here, so **reset the selection to a visible item before hiding a row**, on every platform. [HIG Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) (2026-09-07): don't hide tab bar buttons when content is unavailable; the rows hidden here are sidebar / More-list rows, never one of the four iPhone tabs.
- **Freshness gaps.** Thin pages: the Reminders usage key, the Calendars entitlement, `managedObjectClassName`. No Core Data or CloudKit WWDC session in the last two years; FoundationModels sessions are WWDC26 [241](https://developer.apple.com/videos/play/wwdc2026/241/) and [319](https://developer.apple.com/videos/play/wwdc2026/319/). The docs list tvOS 27.3 beta for `SystemLanguageModel`; the installed SDK doesn't, which doesn't matter here.
