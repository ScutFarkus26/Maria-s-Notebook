## Apple guidance
Checked 2026-11-22 against Xcode 27.2 (27B52), SDK 27.2. Xcode 27.3 Beta 2 exists; its notes change nothing here. The main app targets iOS/iPadOS/macOS 27.0; the Daybook Assistant targets iOS 18.0, so any iOS 26+ API there needs `#available`.
- **A1. Opening one item from a link (Phase 5).** A custom URL scheme (`CFBundleURLTypes`) with `View.onOpenURL` (iOS 14, macOS 11) is enough for links between Danny's own apps; Apple prefers universal links only for links other people follow. Without `handlesExternalEvents`, SwiftUI opens a new window for the URL. The main window already has `.handlesExternalEvents(preferring: ["*"], allowing: ["*"])` (`AppCore/Handoff.swift:111`, from the 2026-10-17 bug hunt), so it claims the URL; the Keyboard Shortcuts, detail and Quick Note scenes must not. `onOpenURL` must sit on a view inside the scene that gets the URL. Validate every part and ignore a malformed URL; a link only opens, never changes. `OpenIntent` needs an `AppEntity` and is for Siri and Spotlight, not needed here. [onOpenURL](https://developer.apple.com/documentation/swiftui/view/onopenurl(perform:)), [handlesExternalEvents](https://developer.apple.com/documentation/swiftui/scene/handlesexternalevents(matching:)), [custom URL scheme](https://developer.apple.com/documentation/xcode/defining-a-custom-url-scheme-for-your-app), all modified 2026-10-08.
- **A2. A row at the largest text sizes (Phase 4).** HIG: "consider using a stacked layout" when text grows in a narrow row. Switch between `HStack` and `VStack` with `AnyLayout` on `@Environment(\.dynamicTypeSize).isAccessibilitySize`, or use `ViewThatFits`; `fixedSize(horizontal: false, vertical: true)` only helps the label wrap by word. `ViewThatFits` alone won't stack a row whose horizontal form still "fits" by squeezing. macOS has no Dynamic Type. [HIG Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), modified 2026-08-06.
- **A3. Clearing a delivered notification (Phase 3).** `UNUserNotificationCenter.removeDeliveredNotifications(withIdentifiers:)` (iOS 10, macOS 10.14) returns at once and removes in the background; nothing says when it's finished. It doesn't touch pending requests, so keep the existing pending removal beside it. [Docs](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/removedeliverednotifications(withidentifiers:)), modified 2026-10-08.
- **A4. A corner control and toolbar buttons on iPad (Phase 4).** Apple has no page on this collision. HIG Toolbars: don't lay out so items overflow; at most three groups; one primary action, trailing. The pattern the SDK offers: make the control a `ToolbarItem(placement: .topBarTrailing)` set apart with `ToolbarSpacer(.fixed)` (iOS 26), or float it in `safeAreaBar`/`safeAreaInset` so content makes room. [HIG Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars), modified 2026-08-20.
